# 腹部多器官分割系统 —— 课程设计文档

> 版本：v1.0  
> 状态：方案锁定，进入 M0 实施  
> 文档定位：可直接作为报告「系统设计」章节的主体

---

## 1. 课题目标

构建一个面向腹部 CT 的多器官自动分割系统：

```
用户上传 DICOM 序列  →  系统重建三维体积  →  深度学习模型分割多器官  →  前端逐层滚动查看结果
```

**核心特征**：输入三维（一个 CT 序列 = 一个 3D 体积），计算三维（3D 卷积网络），呈现二维（逐层渲染，用户像翻片一样观看整个体积）。

---

## 2. 关键设计决策（及理由）

### 2.1 为什么"输入 3D、输出 2D"是正确的

所有 PACS / 阅片软件的架构都是"数据 3D、显示 2D"。分割结果是一个三维掩膜，但人眼一次只能看一个截面。因此：

- **不输出"一张 PNG"**：一张图无法表达 300 层的体积
- **不输出"带标注的 DICOM 序列"**：那属于篡改原始影像，且体积巨大、丢失原始信息
- **输出"查看器 + 数据"**：服务端按 `z` 渲染 PNG 帧，前端滚动查看；同时保留标准数据文件（NIfTI / DICOM SEG）

### 2.2 计算必须是 3D，不能逐层独立 2D 推理

| 做法 | 层间连贯性 | 说明 |
|---|---|---|
| 逐层独立 2D 推理 | ❌ 差 | 相邻层预测独立，滚动时边界闪烁、隔层漏检 |
| 2.5D（z-1, z, z+1 → 中心层） | ✅ 较好 | 折中方案，作为对比实验 |
| **3D 体积推理（采用）** | ✅✅ 好 | 天然连续，`sliding_window_inference` 实现成本低 |

**结论**：呈现是 2D，计算必须是 3D。这一点直接决定演示观感。

### 2.3 输出双通道

| 通道 | 输出物 | 面向 |
|---|---|---|
| 给人看 | 网页滚动查看器（PNG 帧流）、缩略图墙、3D 渲染图 | 任何人，打开即看 |
| 给专业软件 | NIfTI 掩膜、DICOM SEG、metrics.json | 3D Slicer 核验、复现 |

## 4. 系统架构

```
┌─────────────────────────────────────────────────────────────┐
│                        前端 (浏览器)                          │
│  上传面板 │ 滚动查看器 │ 缩略图条 │ 图层切换 │ 指标面板          │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP
┌──────────────────────────▼──────────────────────────────────┐
│                    后端 (FastAPI)                            │
│  /api/upload        接收 DICOM zip / NIfTI                    │
│  /api/case/{id}     病例元信息                                │
│  /api/case/{id}/slice/{z}   按需渲染单层 PNG（带缓存）          │
│  /api/case/{id}/export      导出 NIfTI / SEG                  │
└──────────────────────────┬──────────────────────────────────┘
                           │
┌──────────────────────────▼──────────────────────────────────┐
│                     核心流水线                                │
│  ① DICOM 摄取  →  ② 预处理  →  ③ 3D 模型  →  ④ 后处理  →  ⑤ 渲染 │
└─────────────────────────────────────────────────────────────┘
```

### 4.1 统一的中间表示（关键设计）

模型与输入格式**彻底解耦**：

```python
@dataclass
class Volume:
    pixels: np.ndarray        # float32 [H, W, D]，已转 HU
    spacing: tuple[float,float,float]   # mm
    origin: tuple[float,float,float]
    direction: np.ndarray     # 3x3 方向余弦矩阵
    source: str               # 'dicom' | 'nifti' | 'synthetic'

@dataclass
class LabelMap:
    labels: np.ndarray        # uint8 [H, W, D]，与 Volume 同几何
    spacing: tuple[float,float,float]
```

**任何输入格式都先归一化为 `Volume`**；模型只认 `Volume`；渲染器只认 `Volume + LabelMap`。

### 4.2 DICOM 摄取的五个必做步骤

这一步是工程含量的核心，也是滚动观看是否好看的决定因素：

| # | 步骤 | 做错的后果 |
|---|---|---|
| 1 | **序列选择**：按 `SeriesInstanceUID` 分组，按层数/`ImageType`/`SeriesDescription` 挑出目标序列 | 分割到定位片上 |
| 2 | **HU 转换**：`HU = pixel * RescaleSlope + RescaleIntercept` | 模型输入分布完全错误 |
| 3 | **层序排序**：按 `ImagePositionPatient` 在法向量上的投影排序，**不能**用 `InstanceNumber` | 滚动时层序乱跳 |
| 4 | **方向归一**：用 `ImageOrientationPatient` 构造方向矩阵，重排到统一解剖朝向 | 左右镜像，脾脏跑到右侧 |
| 5 | **各向异性处理**：重采样到各向同性（如 1.5mm），推理后再映回原始网格 | 滚动"一顿一顿"，矢状面拉长 |

> **验收方式**：把原始 DICOM 和分割结果同时拖入 3D Slicer，若自动配准叠加 → 几何处理全对。

## 5. 模型

### 5.1 网络

3D U-Net，**输出通道数可配置**（从第一天就为多器官准备）：

```python
UNet3D(in_ch=1, out_ch=N, features=(32,64,128,256,512), deep_supervision=True)
```

- 输入：`1 × D × H × W`（patch 96³ 或 128³）
- 输出：`N × D × H × W`（N = 1 + 器官数）
- 损失：`DiceCELoss`（多分类 softmax）
- 推理：`sliding_window_inference`，高斯权重融合

### 5.2 类别数规划

| 任务 | out_ch | 说明 |
|---|---|---|
| 单器官（脾） | 2 | 背景 + 脾脏，用于验证链路与迁移学习源域 |
| 多器官（AMOS 8 类） | 9 | 背景 + 肝脾胃肾×2+主动脉+下腔静脉+胰腺 |
| 多器官（AMOS 15 类） | 16 | 全量 |

### 5.3 迁移学习策略

**必须训练新模型，但不必从零**：

1. 加载单器官权重，按形状过滤（自动跳过输出头）
2. 分层学习率：Encoder `1e-5`、Decoder `1e-4`、Head `1e-3`
3. 渐进解冻：前 10 epoch 冻结 encoder，之后全解冻

**不做"冻结底层"的最保守版本**，理由：同域数据、目标数据量足够、多器官任务更难，冻结会限制适应能力。

**并把策略本身做成实验**（报告加分项）：

| # | 初始化 | 轮数 | 8 器官 mDice | 脾脏 Dice |
|---|---|---|---|---|
| 1 | 随机 | 300 | ? | ? |
| 2 | 脾脏热启动 + 全量微调 | 150 | ? | ? |
| 3 | 脾脏热启动 + 冻结 encoder | 150 | ? | ? |
| 4 | 单器官模型（专精参照） | — | — | 0.94 |

> 第 4 行预期揭示「专精 vs 泛化」权衡：单器官模型在脾脏上可能优于多器官模型——这本身是有价值的结论。

## 6. 强化学习模块

**定位：分割后处理精细化，不替代监督学习主干。** 主分割器用 RL 在文献中普遍不敌监督学习，若声称"用 RL 做分割"会在答辩被质疑。

**方案：逐层边界精修 Agent（PPO）**

| 要素 | 设计 |
|---|---|
| 环境 | 单层 slice：原图 + 当前 mask + 符号距离场 |
| 状态 | 局部 patch（如 64×64）+ 距离场 + 当前轮廓点坐标 |
| 动作 | 边界点 8 方向位移 / 停止 |
| 奖励 | ΔDice + 边界距离改善 − 曲率惩罚 |
| 训练 | UNet 冻结后单独训练 PPO |

**为什么选这个**：2D 上可逐步可视化（录成动画），答辩展示效果最强；3D 中无法直观展示 agent 的决策过程。

## 7. 输出规格

| 输出 | 格式 | 用途 |
|---|---|---|
| 逐层叠加图 | 服务端按需渲染 PNG（支持窗宽窗位、透明度、轮廓/填充） | 滚动查看主交互 |
| 缩略图墙 | PNG 网格 | 报告/PPT |
| 3D 渲染 | marching cubes + 离屏渲染 PNG | 答辩展示 |
| 掩膜 | NIfTI | 专业软件核验 |
| 标注对象 | DICOM SEG（可选） | PACS 语境 |
| 指标 | metrics.json（Dice/HD95/ASD/体积） | 实验记录 |

**窗宽窗位默认值**：腹部软组织 WL=40, WW=400（不设窗会导致输出图像灰蒙蒙一片）。
